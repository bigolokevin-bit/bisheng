# 控制台 v2 视觉方向（三选一）— 2026-11-13

> 目的：为「seakoi-agent-os 数字员工管理控制台」重新规划提供 **3 个静态高保真方向稿**，先看方向、再谈施工。
> 三份稿覆盖同一批真实业务数据（员工 / 审批 / 运行 / 审计），差异只在视觉与组织方式，可直接对比。
> 调研依据：`../CONSOLE-REFERENCES.md`（主推荐 = shadcn/ui 外壳 + Dify 式 IA + Langfuse 式 trace 时间线，Tremor 供指标卡）。

## 怎么看

用浏览器直接打开（零依赖，1440 宽最佳），每个文件顶部有一个深色小切换条（评审用，不属于设计）：

| 文件 | 屏 ① 员工列表 | 屏 ② 员工详情 | 屏 ③ 审批详情 |
|---|---|---|---|
| `direction-a.html` | 表格 + 页面头 | 左侧身份栏 + 右侧 Tab（运行含 trace） | 列表 + 右侧详情面板 |
| `direction-b.html` | KPI 条 + 双栏（列表可选中） | 运行列表 + Langfuse 式层级 trace | 双栏审批 + 风险色条 |
| `direction-c.html` | 卡片网格 | 身份横幅 + 分区卡片 | 分组卡片（基本信息/风险/绑定/决策） |

三份稿的颜色都定义为语义变量（`--bg / --surface / --border / --text / --muted / --primary / --danger / --warning / --success`），选定方向后可 1:1 翻译成 Tailwind theme token。

## 方向 A「沉稳工作台」

- **设计意图**：最接近 shadcn/ui Dashboard Blocks 的克制 SaaS 观感——浅灰画布、白卡片、1px 细边框、8px 圆角、沉稳蓝单强调色。目标是「像一套正经的内部管理系统」，评审会上最不容易被挑战的方向。
- **信息层级**：页面头（标题 + 一句说明 + 搜索 + 主操作）→ 状态筛选段控件 → 表格卡片；详情为「左身份栏（版本/负责人/预算/知识/工位/职权）+ 右 Tab（概览/任务/运行/审计）」；审批为「左列表 + 右详情面板」。三级字阶：页面标题 20 / 区块标题 15 / 正文 13.5 / 辅助 12。
- **关键组件**：分组侧边导航（含审批角标）、状态徽标（圆点 + 中文文字）、操作按钮组（查看/暂停/更多，替代文字链）、展开式运行卡（trace 竖轴时间线 + 子步骤 + JSON 详情）、风险说明黄条、批准/驳回/要求修改三键决策区、列表底部空态。
- **适合**：面向财务、IT 治理、传统管理层演示；团队希望改动最小、最快落地（组件全部有 shadcn 现成对应：sidebar / table / tabs / card / drawer 同源）。
- **代价**：性格保守，第一眼「不惊艳」；表格横向列多时 1440 以下会挤；信息密度中等，指挥中心类用户嫌翻页多。

## 方向 B「指挥中心」

- **设计意图**：给管理员/值班同学的「仪表盘」——深色导航包住浅色高密度内容区，顶部 KPI 条给全局态势，主体全部采用「列表-详情双栏同屏」，不用来回跳页。气质对标 Langfuse / OpenHands 的工程控制台。
- **信息层级**：KPI 条（在岗员工 / 今日运行 / 待审批 / 今日成本，含口径注释）→ 左栏可选中列表（每行左侧 3px 状态色条 + 文字徽标 + 岗位版本号）→ 右栏详情 Tab。trace 是主角：层级缩进的 step 树、每步耗时条 + 耗时秒数 + 成本徽标（实测↑ / 虚线=估算），失败步带红条与中文错误说明。三级字阶：15.5 / 13 / 11.5，数字全部 tabular-nums + 等宽字体。
- **关键组件**：环境徽标（PRODUCTION）+ 同步时间戳、⌘K 式全局搜索、迷你筛选器条、耗时归一化小条（非图表堆砌，仅步间相对比较）、`usage=upstream / estimated` 图例、run 关联审计小表、审批「快过期优先」排序 + 倒计时文案。
- **适合**：把控制台当「日常工位」的重度用户（值守、排障、审批吞吐大）；管理层大屏汇报也顺；最能体现「数字员工在干活」的实时感。
- **代价**：密度高，新用户有学习成本；深色导航要与 Bisheng 外壳共存需确认（若宿主已提供全局导航，此方向可退化为浅色壳）；小屏笔记本（<1366）双栏会紧张，需要断点策略。

## 方向 C「现代 Agent 中台」

- **设计意图**：对标 Dify / Langfuse 的产品页气质——暖中性大留白、大标题（27px）、14px 大圆角卡片、柔和阴影 + 单一紫色强调。刻意「不像内部后台，像一个产品」，适合对外展示与争取业务方好感。
- **信息层级**：列表用**卡片网格**（每卡 = 头像/岗位/状态 + 版本/负责人/知识/工位四宫格 + 预算行 + 待办审批与操作），一屏 8 卡含「新建员工」引导位；详情顶部一条**身份横幅**（头像 + 姓名 + 状态 + 版本 + 负责人 + 主操作），下面 4 张指标小卡，再分主副两栏（运行/审计 | 职权/工位/预算/知识）；审批详情按「基本信息 → 理由与变更 → 风险评估 → 绑定对象 → 决策」分组卡片纵向推进，像一次阅读流程。字阶：27 / 15.5 / 13.5。
- **关键组件**：圆角胶囊筛选、状态徽标（描边/虚线让草稿、归档有形状差异）、职权动作 chip（新增动作用强调色标出）、批复意见输入框 + 明确主次按钮（**批准=实心主按钮、驳回=危险描边、要求修改=次按钮**）、待审选择条（含空态占位卡）。
- **适合**：产品化程度最高，适合给业务负责人/客户演示、也适合后续开放给非管理员角色自助查看；前端落地同样只用 Tailwind + Radix 同源组件。
- **代价**：卡片网格扫读效率低于表格（找特定员工更慢）；留白与圆角吃屏幕空间，员工规模上 50+ 后需要切回列表形态；单列纵向审批流在窄屏会更长。

## 三方向 vs 视觉分析「5 个必改项」对照

| 必改项 | 现状问题 | 方向 A | 方向 B | 方向 C |
|---|---|---|---|---|
| **1. 卡片化与栅格** | 内容挤在左 1/3，右侧大片空白，无容器 | 12 列式栅格 + 页面头 + 白卡片包住每块内容，全宽利用 | 双栏定宽栅格（372 + 自适应），KPI 条与分区卡全宽铺开 | 主副两栏 + 3 列卡网格，大留白但仍占满 1440 |
| **2. 文案与数字治理** | ID/毫秒/内部黑话直接上屏 | 所有 snake_case 动作 → 中文（括注原值）；时间 `MM-DD HH:mm`；剩余时间「约 5 小时后过期」；金额带 USD；ID 截断 + 复制样式 | 同 A，另加：成本徽标注明 实测(upstream)/估算(estimated) 口径、毫秒→`0.4s`、环境与时戳治理 | 同 A，另把口径解释写进文案（如「批准=主操作…」说明），面向不熟悉系统的读者最友好 |
| **3. 三级字阶** | 无层级，全是一片同号文字 | 20 / 15 / 13.5 / 12 四级（页面头→卡头→正文→辅助），数字 tabular | 15.5 / 13 / 11.5 + 等宽数字，靠字重与底色分层（密度所限） | 27 / 15.5 / 13.5 / 12，层级最夸张、最好读 |
| **4. 操作按钮化** | 三个一样的蓝色文字链，无主次 | 每行按钮组（查看/暂停/更多），决策区主按钮 + 危险描边 + 次按钮 | 详情头部固定操作区（暂停/编辑/发布新版本=主），trace 区提供 中止/导出 | 明确三级：批准=实心主按钮、驳回=危险描边、要求修改=次；卡片底部单主 CTA |
| **5. 空态与筛选标准化** | 空态只有一行灰字；跨页 Tab 结构不一致 | 段控件筛选（含计数）+ 下拉 chips 统一样式；审批列表底部图标空态 + 引导文案 | 每栏统一「标题 + 计数 + 迷你搜索 + 下拉筛选」栏头；队列为空时的空态卡直接展示在稿内 | 胶囊筛选跨页复用同一组件；待审条末尾放「全部审完」空态占位；草稿/归档状态用虚线与描边区分形状 |

## 初步建议（仅供参考，不替用户拍板）

**优先推荐方向 A「沉稳工作台」作为主干**，理由：

1. **落地成本最低**：与 `CONSOLE-REFERENCES.md` 的主推荐（shadcn/ui + Tailwind + Radix 同源栈）几乎逐组件对应，现有 React 页面可以平迁；
2. **对「太丑」的修复最全面**：5 个必改项全部以业界成熟范式解决，管理层与工程侧都不会有争议；
3. **可扩展性好**：确认方向后，可以把 B 的「trace 层级时间线 + KPI 条」和 C 的「审批分组卡片 + 按钮主次」作为局部增强合并进来——A 是外壳，B/C 的亮点是插件。

如果目标用户以值守/管理员重度使用为主（一天多次处理审批与故障 run），改选 **B**；如果这份控制台还要拿给客户或业务方看，改选 **C**。
