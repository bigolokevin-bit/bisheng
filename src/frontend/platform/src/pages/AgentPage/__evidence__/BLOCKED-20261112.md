## Blocker 1 — identity callback: Bearer vs cookie (fix is OUTSIDE this lane)

The BFF (`apps/console/server.py`, main repo commit 7f69733) validates each request
by calling `GET {CONSOLE_BISHENG_BASE}/api/v1/user/info` with
`Authorization: Bearer <token>`. Live measurement 2026-11-12:

- Bearer callback -> `401 {"detail":""}` (re-probed with a fresh login token)
- cookie callback (`access_token_cookie=<same token>`) -> `200` with full data

So `user/info` only accepts the cookie today; every `/agent-api/*` call is denied
with `console.unauthenticated` regardless of token validity. This contradicts the
B1 note (which claimed Bearer works via `user.py:174`).

Fix (L4/ops lane, not this fork lane): make `_identity_transport` send the cookie
header (or Bisheng-side: accept Bearer on user/info).

Repro: `sh /private/var/folders/2b/bnpsyz450pn98w375q_803yw0000gn/T/opencode/l4p3-login-data2.sh`
then `curl -s http://127.0.0.1:7860/api/v1/user/info -H "Authorization: Bearer $(cat /tmp/l4p3-token.txt)"`.
